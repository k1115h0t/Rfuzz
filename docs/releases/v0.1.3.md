## v0.1.3

### Performance
- Decouple `-order` generation priority from strict batch scheduling, so ordered clusterbomb runs no longer wait for one order batch to fully drain before scheduling more work.
- Add a bounded in-memory case queue for the default scheduler. The queue keeps workers fed without preloading the full Cartesian product.
- Automatically use target-window scheduling for ordered clusterbomb runs when a target keyword is available from `-target-key`, `-precheck-key`, or `-stop-scope`.
- Fast-filter failed `-precheck-key` values before clusterbomb generation when no request budget is set, counting the skipped Cartesian product in progress instead of skipping each combination one by one.
- Add DNS single-flight lookup coalescing, real lookup concurrency limiting, and short negative DNS caching to reduce resolver pressure during large multi-target scans.

### Changed
- Allow `-schedule rotate-window` to be combined with `-order`.
- Keep `-order` as a logical generation priority while favoring high-throughput scheduling for large target lists.
- Update README guidance for ordered clusterbomb and rotate-window scheduling.
- Add `-dns-negative-cache-ttl` and `-dns-max-concurrent` tuning options.

### Notes
- Ordered target-window scheduling may interleave later username/password combinations inside the active target window. This is intentional and avoids the old slow path where one `UFUZZ+PFUZZ` batch had to finish every `URLFUZZ` before more work could be scheduled.
- `-budget-requests` keeps the conservative path for precheck skipping so the request budget semantics do not change.
