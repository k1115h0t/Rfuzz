## v0.2.0

### English

#### Added
- Add header-only response regex matchers: `-mhr` for matching headers and `-fhr` for filtering headers. These rules inspect the response status line and headers without reading the response body.
- Add response-need analysis for matcher/filter configuration. Status-only and header-only jobs now skip response body reads, while size/word/line rules read body stats and `-mr` / `-fr` continue to read the full raw response text.
- Add `-precheck-timeout` for lightweight target prechecks. The default precheck request timeout is now 3 seconds.
- Add HEAD-first precheck probing. Precheck sends `HEAD` first and falls back to `GET` when `HEAD` is not allowed or fails.

#### Changed
- Build raw HTTP request strings lazily. Normal requests no longer construct and clone raw request text; raw request text is built only for dry-run/request-dry-run output and matched raw exchange capture.
- Matched output no longer builds a raw response unless a full-response regex or raw exchange capture needs it.
- Update login/weak-password examples to use `-mhr 'Set-Cookie: ...'` for header-based success checks.
- Bump the package version to `0.2.0`.

#### Notes
- `-mr` and `-fr` keep their existing full raw response semantics and still read the response body. Prefer `-mhr` / `-fhr` for header-only checks such as `Set-Cookie`, `Server`, or `Location`.
- Larger architectural optimizations such as indexed input cases, fixed worker pools, scheduler-side rate limiting, and per-scope in-flight caps remain future work.

#### Verification
- `cargo fmt --check`: passed.
- `cargo test --all --locked`: passed, 87 tests.
- `cargo clippy --all-targets -- -D warnings`: passed.
- `cargo build --release`: passed.

### 中文

#### 新增
- 新增 header-only 响应头正则：`-mhr` 用于匹配响应头，`-fhr` 用于过滤响应头。这类规则只检查响应状态行和 headers，不读取响应 body。
- 新增 matcher/filter 的响应需求分析。只看状态码或响应头的任务会跳过 body 读取；size/words/lines 规则读取 body 统计；`-mr` / `-fr` 继续保持完整 raw response 文本语义。
- 新增 `-precheck-timeout`，用于轻量目标预检查。默认每个预检查请求超时为 3 秒。
- 新增 HEAD 优先的 precheck 探测。预检查会先发送 `HEAD`，当 `HEAD` 不允许或失败时再 fallback 到 `GET`。

#### 变更
- raw HTTP request 字符串改为 lazy 构造。普通请求不再每次构造并 clone raw request 文本；只有 dry-run/request-dry-run 输出和命中 raw exchange 保存时才构造。
- 命中输出不再无条件构造 raw response；只有完整响应正则或 raw exchange 保存需要时才构造。
- 登录/弱口令示例改用 `-mhr 'Set-Cookie: ...'` 表示基于响应头判断成功。
- 将包版本提升到 `0.2.0`。

#### 说明
- `-mr` 和 `-fr` 保留原有“完整 raw response”语义，仍然会读取响应 body。对于 `Set-Cookie`、`Server`、`Location` 这类只看响应头的规则，优先使用 `-mhr` / `-fhr`。
- InputCase 索引模型、固定 worker pool、scheduler 侧限速、per-scope in-flight cap 等更大架构优化仍作为后续工作。

- `cargo fmt --check`：通过。
- `cargo test --all --locked`：通过，87 个测试。
- `cargo clippy --all-targets -- -D warnings`：通过。
- `cargo build --release`：通过。
